The dashboard is at [app.airshipci.com](https://app.airshipci.com), scoped to
one GitHub organization. Organization owners can change things; members can
read.

## The pages

<ResponseField name="Overview" type="is anything wrong right now">
  Jobs and runners at a glance: queued, in progress, succeeded, failed, runner
  minutes, and the p50 and p90 time jobs spent waiting for a machine. Those
  last two are the health metric worth watching.

  </Frame>
</ResponseField>

<ResponseField name="Repositories" type="what is switched on">
  Activate and deactivate repositories, and allow public access where you mean
  to. Each row shows the `airship.yaml` Airship last read from the default
  branch, and whether it parsed.

  This page also has the **config checker**: paste a file, see whether it
  parses and what machines it would plan. Cheaper than a push.

  **Move workflows** reads a repository's `.github/workflows`, picks out the
  jobs on GitHub-hosted runners, suggests a runner for each kind of machine
  they use, and shows the `airship.yaml` and `runs-on` changes as a diff. It
  then opens a pull request, or you copy the files. Nothing changes until the
  pull request is merged, and your choices are kept in the browser so you can
  stop and come back. Organization owners only.
  [Move your workflows](/move-workflows) walks through it.

## Which page, when

| The question | The page |
| --- | --- |
| Why is my job still queued? | **Jobs** — it states the reason |
| Why did the launch fail? | **Events** — your cloud's own message |
| Which machine is this job on? | **Runners** — state, instance ID, region |
| Is my config file valid? | **Repositories** — the checker |
| Has my credential expired? | **Cloud** — last verified, and its status |
| Are we at the cap? | **Overview** for queue waits, **Settings** for the cap |
| Why is CI slower this week? | **Analytics**, then **Events** for degraded caches |
| Who has access? | **Teams** for people, **API keys** for tokens |

## Events worth recognising

| Kind | Means |
| --- | --- |
| `runner.launched` | A machine was created |
| `runner.launch_failed` | A launch failed; the message is your cloud's |
| `runner.launch_unconfirmed` | The answer to a launch was lost; it reconciles |
| `runner.lost` | A machine disappeared without finishing a job |
| `config.invalid` | An `airship.yaml` stopped parsing; the detail names the field |
| `cache.unavailable` | A cache-enabled runner launched without acceleration |
| `job.skipped` | A job asked for an Airship label and will not be served |
| `cloud.credentials_rejected` | Your cloud refused the credential |
| `access.updated` | `access.yaml` changed |
| `migration.proposed` | **Move workflows** opened a pull request |
| `repository.activated` | Someone switched a repository on |

<Tip>
  `cache.unavailable` is the quiet one. A cache-enabled job that loses
  acceleration still passes — just slowly — so nothing fails and nobody
  notices until the bill or the clock does. It is worth watching.
</Tip>

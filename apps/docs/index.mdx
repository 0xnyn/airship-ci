Airship gives you fully managed GitHub Actions runners in your own AWS,
Google Cloud, or Azure account. Connect a cloud, activate a repository, and
commit an `airship.yaml` that describes the runners you want. Airship
provisions a runner as each job is queued and terminates it when the job
ends.

There is no runner provisioning, management, or maintenance: no autoscaling
group to tune, no runner image to keep alive, no agent to upgrade. Runners
launch in your regions and bill to your cloud account, so your existing cloud
credits cover the compute.

```yaml airship.yaml
runners:
  - name: build
    cloud: aws
    instance_type: [c7i.2xlarge, m7i.2xlarge]   # tried in order
    region: eu-west-1
    labels: [airship-build]
    extra_config:
      cache: true
```

```yaml .github/workflows/ci.yml
jobs:
  test:
    runs-on: airship-build--${{ github.run_id }}
    steps:
      - uses: actions/checkout@v4
      - run: make test
```

That is the whole integration. Jobs on `ubuntu-latest` are untouched, so you
can move one workflow at a time.

  <Card title="Machines GitHub does not rent you" icon="cpu">

  <Card title="Your cloud's prices, including spot" icon="receipt">

    capacity with an on-demand fallback is two lines of YAML.
  </Card>
  <Card title="One job per machine, always" icon="shield-check">
    A runner registers for a single job and the machine destroys itself
    afterwards. No job inherits another's disk, environment or credentials.

  <Card title="Caching without a size limit" icon="database">
    `actions/cache` and everything built on it, served from a bucket in your
    own account over the local network.
  </Card>
  <Card title="Configured as code, per branch" icon="git-branch">
    A job reads `airship.yaml` at its own commit, so a pull request can try a
    bigger machine before anyone merges it.
  </Card>
  <Card title="Your network, your boundary" icon="network">
    Private subnets, your own egress rules, no inbound ports, and no SSH key
    for Airship to hold.
  </Card>

## What Airship never holds

Your source code, your Actions secrets, your artifacts and your job logs
never reach the control plane — the runner talks to GitHub directly. Your
cloud credential never reaches a runner. Airship holds job metadata and a
sealed credential it opens for the length of one API call.

[Security and trust](/security) is written to be read adversarially, and says
plainly where the edges are.
